# Steam Library Stage 1 Canonical Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **Every delegated worker must be told not to invoke or spawn subagents.**

**Goal:** Build stable account-scoped owned-copy identities, canonical Room storage, conservative matching, and an idempotent shadow projection for Steam, GOG, Epic, Amazon, and custom games without changing current library cards or action routing.

**Architecture:** Existing source tables remain authoritative. Source adapters emit stable metadata snapshots and resolve durable copy keys back to current source rows; a deterministic resolver and one Room transaction update an additive canonical projection. Canonical IDs are opaque UUIDs, account scopes are one-way hashes, incomplete source snapshots never erase prior relationships, and all public UI/action paths continue to use their current source-native IDs until Stage 2.

**Tech Stack:** Kotlin 2.1.21, Room 2.8.4, Hilt, DataStore Preferences, coroutines/Flow, kotlinx.serialization, JUnit 4, Robolectric, AndroidX Room migration testing, existing bounded `FeatureDiagnostics`

## Stage boundary

This plan implements only Stage 1 from `docs/superpowers/plans/2026-07-27-steam-library-staged-roadmap.md`.

In scope:

- Opaque immutable canonical UUIDs.
- Structured `OwnedCopyKey(accountScope, source, stableSourceId)` values.
- Non-secret account scopes for all five sources.
- Additive canonical Room entities, constraints, DAOs, and v25→v26 migration.
- Explicit non-destructive support for public database versions 17–25.
- An explicit destructive recovery limitation for versions 7–16, whose existing 16→17 migration gap cannot be repaired from the exported schemas with confidence.
- Read-only source snapshots and source-row resolution.
- Revisioned Steam PICS genre, category, and tag parsing.
- Direct Steam resolution, stored user decisions, validated direct-map boundaries, conservative exact matching, and unmatched/review-required fallback.
- Transactional merge, unmerge, correction, rejection, reset, and presence updates.
- An always-on but disableable shadow coordinator and aggregate privacy-filtered diagnostics.
- Tests proving idempotence, rollback, account separation, source completeness semantics, and legacy behavior isolation.

Out of scope until later stages:

- Replacing `LibraryViewModel`, `LibraryAppScreen`, source tabs, counts, cards, or pagination.
- Sending canonical IDs through current launch intents, frontend sync files, containers, downloads, saves, or shortcuts.
- Executing install/play/update/uninstall/save actions through canonical adapters. Stage 1 resolves copy keys to source references only; Stage 2 captures and revalidates executable action targets.
- A Copies chooser, preferred-copy UI, deduplicated public cards, or match-correction UI.
- Steam public-catalog fallback for non-owned AppIDs, localized tag labels, discovery controls, popularity, native details, reviews, or discussions.
- Optional network resolvers and fuzzy-search implementation. The Stage 1 resolver represents those results as review-required only when a trusted test/provider supplies a candidate; no current SteamGridDB autocomplete or HLTB title result is promoted to canonical identity.

## Non-negotiable invariants

1. `canonicalId` is a UUID string generated by GameNative. It never encodes a source, account, title, or Steam AppID and is never rewritten.
2. `OwnedCopyKey` remains three structured fields in memory and three Room columns. Do not serialize the whole key into a source-prefixed or Base64 blob.
3. `stableSourceId` formats are source-owned:
   - Steam: decimal Steam AppID.
   - GOG: `GOGGame.id` unchanged.
   - Epic: reversible Base64URL encoding of `namespace` and `catalogId`; never generated `EpicGame.id`.
   - Amazon: `productId`; `entitlementId` remains a separately resolved action field.
   - Custom: decimal ID persisted in `.gamenative`.
4. Account scope is `SHA-256("gamenative-owned-copy-scope-v1\u0000<source>\u0000<provider-account-key>")` encoded as 64 lowercase hex characters. Raw SteamIDs, account IDs, usernames, tokens, and Amazon device/client values never enter canonical tables or feature diagnostics.
5. Amazon has no trustworthy provider account ID in the current API. Its account key is a random `profile_scope_id` stored beside credentials, retained on refresh, and deleted on logout.
6. Source tables and `.gamenative` files remain authoritative. Canonical tables do not persist tokens, manifests, install paths, containers, entitlement payloads, or volatile install/download/save state.
7. A `COMPLETE` source snapshot may mark missing rows absent. A `PARTIAL` or `UNAVAILABLE` snapshot may only upsert observed rows; it never marks a previous relationship absent or deletes a user decision.
8. Projection collection occurs outside Room, then every canonical write for that run occurs in one `withTransaction` block. Process death or any exception rolls the run back.
9. User-confirmed and user-rejected decisions outrank every automatic result until explicit reset.
10. Unknown app type, incompatible app type, conflicting known developers, release-year differences greater than one, multiple exact candidates, indirect GOG joins, and unverified resolver candidates never auto-merge.
11. Stage 1 diagnostics contain aggregate source names, counts, durations, methods, confidence values, reason codes, and error classes only. They never contain titles, candidate titles, copy keys, account scopes, source-native IDs, paths, URLs, credentials, or user text.
12. `LibraryViewModel`, `PluviaMain`, source app screens/managers, existing external launch contracts, and frontend sync ID formats do not consume canonical data in this stage.

- [ ] **Step 4: Implement the identity types and codecs**

Use these public contracts:

```kotlin
@JvmInline
value class CanonicalGameId(val value: String) {
    init {
        val parsed = UUID.fromString(value)
        require(parsed.toString() == value.lowercase(Locale.ROOT))
    }

    companion object {
        fun parse(value: String): CanonicalGameId = CanonicalGameId(value)
        fun random(): CanonicalGameId = CanonicalGameId(UUID.randomUUID().toString())
    }
}

@JvmInline
value class AccountScope(val value: String) {
    init { require(FORMAT.matches(value)) }

    companion object {
        private val FORMAT = Regex("[0-9a-f]{64}")
        fun parse(value: String): AccountScope = AccountScope(value)
    }
}

data class OwnedCopyKey(
    val accountScope: AccountScope,
    val source: GameSource,
    val stableSourceId: String,
) {
    init { require(stableSourceId.isNotBlank()) }
}

object EpicStableSourceId {
    private val encoder = Base64.getUrlEncoder().withoutPadding()
    private val decoder = Base64.getUrlDecoder()

    fun encode(namespace: String, catalogId: String): String {
        require(namespace.isNotBlank() && catalogId.isNotBlank())
        return listOf(namespace, catalogId).joinToString(".") {
            encoder.encodeToString(it.toByteArray(StandardCharsets.UTF_8))
        }
    }

    fun decode(value: String): Pair<String, String> {
        val parts = value.split('.')
        require(parts.size == 2)
        return parts.map { String(decoder.decode(it), StandardCharsets.UTF_8) }
            .let { it[0] to it[1] }
    }
}
```

Define `CanonicalIdGenerator` as a `fun interface` so projection tests can inject deterministic IDs. Do not add a generic parser that accepts legacy `SOURCE_<number>` strings.

- [ ] **Step 3: Implement one idempotent transaction**

1. For each `COMPLETE` batch, call `markAbsentForCompleteSnapshot(accountScope, source)`.
2. Skip writes for `UNAVAILABLE` batches.
3. Process observed copies in deterministic source/key order.

- [ ] **Step 3: Implement deterministic merge helpers**

All public methods use `db.withTransaction`. Merge order:

1. select survivor using confirmed Steam association, then oldest `createdAt`, then lexical UUID;
2. union facets with `INSERT IGNORE` semantics;
3. copy only missing survivor locale/country snapshots;
4. combine preference fields independently, survivor non-null first;
